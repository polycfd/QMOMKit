# Developer glossary

This glossary is a navigation aid for common QMOMKit developer symbols and
concepts. Please follow the linked design page for more detailed explanations,
conventions, and extension rules.

## Frequently encountered symbols

| Category | Symbol | Description | More information |
|---|---|---|---|
| Concept | adaptive branch counts | CQMOM policy that lets branch-local inversions return fewer nodes when the local moments support a lower-order rule. Developers encounter it when fixed rectangular storage gives way to ragged terminal quadrature. | [cqmom_recursive.md](cqmom_recursive.md) |
| Concept | CQMOM | Multidimensional conditional quadrature reconstruction. It is the method behind QMOMKit's phase-space hierarchy, conditioning order, and terminal quadrature workflows. | [cqmom_recursive.md](cqmom_recursive.md) |
| Concept | generalized moment | Moment-like quantity evaluated from an existing quadrature with arbitrary finite real exponents. It is derived post-processing, not a native QMOM/CQMOM reconstruction, phase-space evolution, or realizability moment. | [numerical_conventions.md](numerical_conventions.md) |
| Concept | `QmomMomentBoundaryContribution` | Optional callback concept for additive raw-moment rates from phase-space boundary exchange. It appears in phase-space evolution code where source rates and boundary exchange are composed. | [phase_space_evolution_design.md](phase_space_evolution_design.md) |
| Concept | physics callbacks | Caller-owned velocity, source, and boundary functions that supply model behavior. Developers see them at the boundary between QMOMKit's numerical phase-space evolution utilities and application physics. | [phase_space_evolution_design.md](phase_space_evolution_design.md) |
| Type | `PhaseSpaceVelocity` | Packed velocity callback: fills a library-supplied buffer with dxi/dt for every terminal node at once, node-major. The only velocity form the library carries internally. | [phase_space_evolution_design.md](phase_space_evolution_design.md) |
| Type | `PerNodePhaseSpaceVelocity` | Per-node convenience velocity shape, adapted to the packed form by `make_phase_space_velocity`. Costs one call and one returned vector per node per evaluation. | [phase_space_evolution_design.md](phase_space_evolution_design.md) |
| Type | `QmomMomentSource` | Raw-moment rate callback, evaluated once per SSP-RK stage. It returns its rates rather than filling a buffer; that asymmetry with the velocity is deliberate and is explained on the design page. | [phase_space_evolution_design.md](phase_space_evolution_design.md) |
| Type | `OdeRhs` | Generic ODE right-hand side used by both Runge-Kutta drivers. It fills a supplied derivative buffer, which is what keeps the stage evaluations of an integration free of heap allocation. | [phase_space_evolution_design.md](phase_space_evolution_design.md) |
| Concept | QMOM | One-dimensional quadrature reconstruction from a raw moment sequence. It is the base workflow for ordinary QMOM and for branch-local inversions inside CQMOM. | [qmom_wheeler.md](qmom_wheeler.md) |
| Concept | quadrature | Discrete weighted-node representation of raw moments. It is the object developers inspect, evolve, write out, or use to reconstruct moments after a successful inversion. | [numerical_conventions.md](numerical_conventions.md) |
| Concept | raw moments | Unnormalized moments of the number density function, with $m_0$ carrying total number density. This convention drives initialization, reconstruction, phase-space evolution, output, and validation. | [numerical_conventions.md](numerical_conventions.md) |
| Concept | realizability | Support-aware validity of a truncated moment sequence. Developers encounter it when deciding whether moments can be accepted before reconstruction or during source evolution. | [realizability.md](realizability.md) |
| Type | `ConditioningPath` | Records node indices by CQMOM conditioning level. Developers see it in adaptive diagnostics and ragged terminal quadrature paths. | [cqmom_recursive.md](cqmom_recursive.md) |
| Type | `ConditioningPathTable` | Contiguous table of equal-depth terminal conditioning paths, returned by `CqmomQuadrature::terminal_paths()`. | [cqmom_recursive.md](cqmom_recursive.md) |
| Type | `ConditioningPathView` | Non-owning view of one path in a `ConditioningPathTable`, indexed by conditioning level. | [cqmom_recursive.md](cqmom_recursive.md) |
| Type | `CqmomPreparedCase` | Normal CQMOM problem definition for configured workflows. It holds the initial moments and reconstruction policies together with the recursive branch structure the hierarchy implies, so repeated reconstructions do not rebuild it. | [cqmom_recursive.md](cqmom_recursive.md) |
| Type | `CqmomCase` | Open CQMOM case definition mirroring `QmomCase`: the required moments and every reconstruction setting. Callers build or edit it in code, then construct a `CqmomPreparedCase` from it; its own `compute_cqmom(...)` and `initial_state()` rebuild the recursive branch structure on every call. | [cqmom_recursive.md](cqmom_recursive.md) |
| Type | `CqmomMomentData` | Value container for the required CQMOM moments of a hierarchy. Every CQMOM case and state stores its moments in it, and output and moment replacement use it too. | [cqmom_recursive.md](cqmom_recursive.md) |
| Type | `CqmomMomentLayout` | Describes the hierarchy and required raw moment multi-indices for CQMOM moment data. It keeps values and moment-order metadata aligned. | [cqmom_recursive.md](cqmom_recursive.md) |
| Type | `CqmomMomentRate` | Rate vector returned by CQMOM source and boundary callbacks. It carries one derivative value for each entry exposed by `CqmomSourceContext`. | [phase_space_evolution_design.md](phase_space_evolution_design.md) |
| Type | `CqmomQuadrature` | Public container for multidimensional terminal quadrature. Developers use it for fixed rectangular CQMOM output and adaptive ragged results through the same interface. | [cqmom_recursive.md](cqmom_recursive.md) |
| Type | `CqmomSourceContext` | Representation-neutral view of the CQMOM moments that need source or boundary rates. It lets callbacks use ordered moment information without depending on internal storage. | [phase_space_evolution_design.md](phase_space_evolution_design.md) |
| Type | `CqmomState` | Evolving CQMOM runtime state used by configured phase-space evolution. It carries moments and reconstruction policy between time steps while keeping representation details hidden. | [phase_space_evolution_design.md](phase_space_evolution_design.md) |
| Type | `MomentSet` | One-dimensional raw moment sequence in ascending order. It is the common input shape for QMOM, one-dimensional realizability checks, and source updates. | [numerical_conventions.md](numerical_conventions.md) |
| Type | `MultiIndex` | Phase-space-order vector of moment or node indices. Developers use it to name multidimensional tensor entries, selected moments, and CQMOM node locations. | [numerical_conventions.md](numerical_conventions.md) |
| Type | `MultiIndexTable` | Contiguous table of equal-rank multi-indices, stored row-major so a table of `n` indices costs one allocation instead of `n + 1`. Carried by `CqmomMomentLayout`, `IndexedMomentSet`, and `CqmomSourceContext`. | [cqmom_recursive.md](cqmom_recursive.md) |
| Type | `MultiIndexView` | Non-owning view of one row of a `MultiIndexTable`. It converts implicitly from an owning `MultiIndex` and from a braced list, so read-only call sites are unchanged; like any view it must not outlive its table. | [cqmom_recursive.md](cqmom_recursive.md) |
| Type | `OutputOptions` | Driver-controlled output policy parsed from configuration. It records output intent without making numerical algorithms write files. | [output_design.md](output_design.md) |
| Type | `PhaseSpaceHierarchy` | CQMOM hierarchy that owns node counts by phase-space dimension and the conditioning-order permutation. It anchors ordering rules across reconstruction, callbacks, and output. | [numerical_conventions.md](numerical_conventions.md) |
| Type | `QmomCase` | Configured one-dimensional QMOM problem definition. It gathers the moment sequence, requested node count, and inversion options used by the QMOM workflow. | [qmom_wheeler.md](qmom_wheeler.md) |
| Type | `QmomResult` | Result object for one-dimensional QMOM reconstruction. Developers check it for success before using returned weights, abscissas, or diagnostic messages. | [qmom_wheeler.md](qmom_wheeler.md) |
| Type | `Quadrature1D` | One-dimensional quadrature rule with paired abscissas and weights. It is the lower-level representation used directly by Wheeler utilities and QMOM output. | [qmom_wheeler.md](qmom_wheeler.md) |
| Function | `advance_qmom_moments_with_source(...)` | Advances raw moments through caller-supplied source and optional boundary rates. Developers use it for the source-only part of phase-space evolution or inside composed workflows. | [phase_space_evolution_design.md](phase_space_evolution_design.md) |
| Function | `advance_nodes(...)` | Advances quadrature abscissas through a phase-space velocity field while preserving weights and paths. It is the lower-level operation behind phase-space evolution. | [phase_space_evolution_design.md](phase_space_evolution_design.md) |
| Function | `advance_cqmom_phase_space(...)` | Performs a full CQMOM phase-space evolution macro step. It composes reconstruction, node advection, moment-source evolution, and state update for CQMOM workflows. | [phase_space_evolution_design.md](phase_space_evolution_design.md) |
| Function | `advance_qmom_phase_space(...)` | Performs a full QMOM phase-space evolution macro step from an accepted `QmomState`. It is the one-dimensional path that composes node advection, moment-source update, active-node selection, and moment reconstruction. | [phase_space_evolution_design.md](phase_space_evolution_design.md) |
| Function | `compute_cqmom(...)` | Runs multidimensional CQMOM reconstruction for a configured or an explicit case. Developers use it to produce terminal quadrature and reconstruction diagnostics. | [cqmom_recursive.md](cqmom_recursive.md) |
| Function | `compute_qmom(...)` | Runs one-dimensional QMOM reconstruction. It wraps the Wheeler inversion workflow and returns the public QMOM status and quadrature data. | [qmom_wheeler.md](qmom_wheeler.md) |
| Function | `evaluate_generalized_moment(...)` | Evaluates generalized moments from one-dimensional or CQMOM quadrature as derived post-processing values. | [qmom.md](../user/qmom.md) |
| Function | `load_cqmom_prepared(...)` | Loads a `.qmom` file into the normal representation-independent CQMOM workflow. Developers encounter it in configured examples, validation cases, and phase-space evolution setup. | [configuration_design.md](configuration_design.md) |
| Function | `load_qmom(...)` | Loads a `.qmom` file into a validated one-dimensional QMOM case. It is the configuration entry point for repeatable QMOM workflows. | [configuration_design.md](configuration_design.md) |
| Function | `reconstruct_cqmom_moments(...)` | Reconstructs lean CQMOM required moments from terminal quadrature using a layout. Developers use it for validation, output, and phase-space evolution handoffs in lean workflows. | [cqmom_recursive.md](cqmom_recursive.md) |
| Function | `reconstruct_raw_moments(...)` | Reconstructs raw moments from accepted quadrature output. It is the handoff back to moment storage after node motion and a common validation check. | [phase_space_evolution_design.md](phase_space_evolution_design.md) |
| Important internal helper | `compute_recursive_quadrature` | Internal recursive assembly routine behind public CQMOM reconstruction. Developers encounter it when tracing branch traversal, diagnostics, and terminal quadrature construction. | [cqmom_recursive.md](cqmom_recursive.md) |
| Important internal helper | `CqmomMomentView` | Internal non-owning adapter for reading root moments uniformly, whether they come from a full tensor or an indexed set. It lets recursive CQMOM stay independent of the owning input representation. | [cqmom_recursive.md](cqmom_recursive.md) |
| Important internal helper | `IndexedMomentSet` | Internal lookup storage for lean CQMOM moments. It gives recursive reconstruction deterministic access to required moments without exposing sparse storage as public API. | [cqmom_recursive.md](cqmom_recursive.md) |
